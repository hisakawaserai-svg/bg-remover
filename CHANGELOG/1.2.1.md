## 変更の記録

### 修正

- 日本語ロケールで Android のアプリ名が英語「Sticker Cutout」のままだった。`values-ja/strings.xml` を追加して「スタンプ抜き」にした。1.2.0 の iOS 側の同名の修正（3652ac9）に相当する Android 側の対応 (616aac0)
- 木目のように背景が細かく分かれた写真の色ベース処理で、Hermes（JS の実行エンジン）がネイティブクラッシュ（SIGSEGV）したり、約40秒かかったりしていた。原因は、皮むき（`peelOnce`）が境界の画素ごとに `floodFill` を呼び、呼ぶたびに `Int32Array(w * h)`（1875x2500 で約18.75MB）を確保していたこと。バッファを1つ使い回すようにした。除去結果（透過画素数）は変わらない。エミュレータで 4/4 回クラッシュ → 5/5 回成功、皮むき区間は約1.4秒から約0.08秒に短縮。実機（Samsung）でも確認 (b4154fb)
- Android で被写体検出が失敗したときの「色ベースで試す／キャンセル」の選択肢が `ActionSheetIOS` だったため、Android では `ActionSheetManager doesn't exist` の例外になり、色ベースへ切り替える導線ごと使えなかった。Android は `Alert.alert` にした（iOS は従来どおり） (e8fdc05)

### その他

- Android の release で R8（縮小・最適化）を有効にした。Play Console の「DEX code optimization is below our threshold」警告への対応。DEX は 3 本 約23.3MB から 2 本 約10.2MB になった。keep ルールの追加は無し。実機で起動・Skia 描画・保存・AsyncStorage・被写体検出・広告・共有受信・レビュー要求・Reanimated が動くことを確認 (5757a5f)
- Android のビルド番号を 13 に上げた（12 は Play にアップロード済みのため） (aed0d9e)
- `mapping.txt`（R8 の難読化解除）と `native-debug-symbols.zip` を Play Console にアップロードする

## 未着手

- 被写体検出のモデルが初回に未ダウンロードのとき、生の英語エラー（`Waiting for the subject segmentation optional module...`）が「切り抜けなかった」と同じ扱いになる。「準備中です」のような別の案内にしたい
- 初回オンボーディングの吹き出しが、`numberOfLines={2}` のため長い文言で「...」に切れる（Samsung 実機で確認。支障は小さい）
- `floodFill` が画素ごとに小さな配列（隣接4画素）を作っている。クラッシュの原因ではないが、処理を軽くできる余地がある

### 次のアップデートで対応する（Play Console の「推奨される行動」）

1.2.1 のアップロード後に Play Console に出た提案。審査の合否には関係しない。次の共通リリース（1.3.0 など）で、1 つずつ変えて 1 つずつ確かめる。

- R8 の最適化が無効: `proguardFiles` を `proguard-android.txt` から `proguard-android-optimize.txt` に変える（今の方は `-dontoptimize` を含む）
- リソース縮小が無効: `shrinkResources true`（名前で探している画像・文字列が消されないか要確認）
- エッジツーエッジ表示と、システムバー周りの非推奨 API（多くは React Native 本体・依存ライブラリ由来）
- 大画面でのリサイズと向きの制限（縦向き固定は意図した仕様。Android 16 以降は大画面で無視される）
- ビットマップ画像の最適化
- Android Gradle Plugin 9.0 以降へ（React Native の対応待ち。今は 8.12.0）
