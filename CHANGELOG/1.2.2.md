## 変更の記録

### 変更

- 自動分割画面から「分割の細かさ」スライダーをなくした。行数・列数のステッパーで直接調整する方が早く、スライダーは不要だった。スポイト・取り消し・やり直しの後の列数の再推定は、初期推定と同じ既定の定数を使う（過去にスライダーを動かした人だけ、保存値のせいで初期推定と基準がズレていたのも、これで揃う）。スライダーの確定時にしか読まれていなかった `colsManualRef` も消した。`store.ts` の `splitTolerance` キーと `toleranceToGapParams` は保存データとテストのために残した (2d262b6)
  - 実機確認（未）: 初期の行数・列数が今まで通りか / スポイト後に再推定されるか / 列ステッパー手動操作後にスポイトしても壊れないか
- 自動分割画面に「線の位置をリセット」ボタンを足した。行数・列数はそのままで、動かした線を等分割に戻す。カードの中、列数と「分割しない」の間。線がすでに等分割のときと「分割しない」のときは押せない (2972bc7)。線の移動は取り消せないので、押すと確認を出す (5b2d296)

- 背景を消した直後に「背景を消す」画面（`RemoveBgScreen`）を毎回挟むようにした。祖父母世代に「市松模様＝透明」が伝わらず、数秒で消えるトーストでは背景が消えたことが分からなかったため。元の画像と消した後をトグルで見比べられ、最初に元の画像から消した後へ切り替わるアニメーションを1回だけ出す。流れは 背景を消す → 分割設定 → 分割結果。分割設定の「戻る」はこの画面へ、この画面の「戻る」はホームへ。ホームの一覧から再開したときは分割設定へ直接進む (1fda5db, 033b3f3)
  - 背景の道具（スポイト・取り消し/やり直し/最初に戻す・消し方の切り替え）を分割設定からこの画面へ移し、分割設定は分割だけにした。左下の✨ボタンはなくした
  - 「強さ」は設定画面の「自動除去の強さ」と同じスライダー（人物アイコン⇔画像アイコン、目盛りに吸着）。変えた値はこの画像だけに使い、設定は変えない。スポイトの編集は残したまま、最初の自動除去だけをやり直す。被写体検出で消したときは強さが効かないので、薄くして押せなくする (b73f8b9, cbf3283)
  - 「消し方」（色ベース／被写体を検出）もこの画像だけ。スポイトの編集があるときは、消えることを確認してから消し直す。被写体検出が使えない端末ではタブごと出さない
  - 画面全体をスクロールできるようにした（小さい画面で道具に届かないため）。下地（市松／白／黒）の切り替えボタンを「元の画像を見る」の右に置いた（画像には重ねない）。元の画像を表示しているとき、左の四角に背景とみなした色を出す（2色なら斜めに区切る） (3c24b3e)
  - 設定画面の「自動除去の強さ」のスライダーにも、同じ人物・画像のアイコンを付けた
  - 開閉のアニメーションは Reanimated の entering/exiting と LayoutAnimation が効かない（途中で止まって透明のまま残る）ため、`withTiming` で高さと透明度を自前で動かしている（`Collapsible`）。端末の「視差効果を減らす」がオンでも動くよう `ReduceMotion.Never` を指定した
- ローディングを共通の部品（`LoadingView`）にそろえた。半透明で重ねる使い方（`overlay`）と、暗い画面用の黒い半透明（`dark`）を足した。背景を消す画面のスポイト・強さ・取り消し・やり直し・リセット、ホームの読み込み中、プレビューの準備中、保存した画像の読み込み中、範囲の調整のスポイト中で使う。重い計算の前に「ローディングを出す → 2フレーム待つ」流れは `runBusy` にまとめた (3c24b3e, 8c57013)

### 修正

- 分割結果画面の見出し横のボタン類（元画像・番号・下地）が、英語ではヒント文と一緒に改行されて左に寄っていた。ボタン類を1つにまとめて右端に寄せた (a7553e1)
- 「分割しない」で先へ進んでから戻り、チェックを外すと、動かしておいた線が等分割に戻っていた。`doSplit` とセッション保存で、noSplit のときは線の位置（bounds）を捨てていたため。noSplit の切り出しは bounds を使わないので、常に残すようにした (76b8917)

- 「分割しない」で切った後、分割結果の「リセット」で等分割に切り直されていた。リセットが「分割しない」を常にオフで渡していたため。「分割しない」を App 側で覚え、リセット・分割設定へ戻ったとき・作業の再開で引き継ぐ。あわせて、カットの編集・合体の保存で線の位置と列数が記録から消えていたのと、ホームへ戻った後に前の画像の線が次の画像へ持ち越されていたのも直した (1f7f7a7)
- アプリを作り直した後、範囲の調整のツールメニューが枠だけ出てボタンが透明になっていた。Reanimated の entering/exiting が途中で止まるため。ツールメニュー・畳んだズームのボタン・保存完了の「保存しました」から外した。アプリ内に entering/exiting は残っていない (58390ec)
- ホームの読み込み中のローディングが、下の広告まで覆っていた。広告に重ねるのは AdMob のポリシー違反になる。`Screen` に `overlay` を足し、ヘッダーとフッターの間だけを覆うようにした (6d473e5)
- ホームの一覧で、背景を消してから分割せずに戻った作業が「未処理」と出ていた。作業の記録が「透過済み」に変わるのは分割したときだけだったため。「背景を消す」画面に来た時点で「透過済み」にする（自動で消していないときと、分割済み・書き出し済みの記録は変えない）
- 使い方・チュートリアルを新しい画面に合わせた。使い方に「背景を消す」タブを足し（6タブを3個×2段に並べる）、背景を消す画面の「？」から開く。「流れ」に「背景を消す」の手順を足した。「自動分割」タブから「分割の細かさ」・スポイト・方式の切り替え（左下のきらきら）を外し、「線の位置をリセット」を足した。「困ったとき」の背景と方式の説明を、背景を消す画面で直す内容に書き直した。はじめてガイド2枚目と、複雑なシートのチュートリアルの見本から「分割の細かさ」のスライダーを外し、列数のステッパーを足した
- 「自動除去の強さ」の説明を「背景に近い色まで広く抜けます」から「人物優先にするほど人物が残りやすく、背景優先にするほど背景が消えやすくなります」に変えた（設定画面・背景を消す画面・使い方で共通）。消し方を変えるときは、スポイトで消していなくても毎回確認を出す（強さも戻るため）。
- はじめてガイドの2枚目に「背景を消す」の1枚を足した（全5枚）。背景が消える → 元の画像と見比べる → 下地を月（黒）にして消えすぎた所を見つける → 強さを人物優先へ2回に分けて動かして戻す → 分割へ進む、を1枚でループする（26秒）。SVG は使わず、今ある鳥・吹き出し・タップ表示・市松の部品と View の組み合わせで作った。ほかの枚と同じ暗い地色と day/night の2体を使う。消えすぎた所は夜の鳥の白い体に丸を重ねて表し、市松では紛れる薄い灰色、黒では黒で描く (OnboardingStepBg)
- 設定の「チュートリアルをもう一度見る」を「はじめてガイドをもう一度見る」にした（日本語のみ）。リリースノートで使う呼び方と画面の表示をそろえるため
